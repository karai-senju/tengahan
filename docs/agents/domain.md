# Domain docs

Single-context repo: one `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

- Before exploring, read `GLOSSARY.md` and any ADRs in `docs/adr/` that touch your area. If they don't exist, proceed silently.
- Use the glossary's terms in issue titles, test names and code; don't drift to the synonyms it lists under _Avoid_.
- If your work contradicts an ADR, say so explicitly instead of silently overriding it.
